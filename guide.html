Development guide

Connect to your computer.

PocketCPU pairs a native iPhone or iPad client with a host you control.

The project is in development. A public App Store build and consumer companion installer are not available yet. These notes describe the current workflow.

What you need

  • An iPhone or iPad running iOS or iPadOS 17 or later.
  • Your own Mac or Linux computer, a PocketCPU development build, and OpenCode installed separately.
  • A model configured in OpenCode. Any provider account, usage charges, and hosting are separate from PocketCPU.
  • An HTTPS address with a certificate your device trusts.

Windows development archives are cross-built, but native Windows runtime, ACL, networking, and device testing remain outstanding. WSL2 remains an interim development route when OpenCode and PocketCPU run in the same Linux environment.

Pair a development build

  1. Run OpenCode on the host. Keep its server on loopback with authentication, and retain its permission policy.
  2. Configure PocketCPU. The host owner chooses the project directories and HTTPS route. The companion never needs a public, unauthenticated OpenCode port.
  3. Create a pairing code. Run the host's pairing command, then enter the HTTPS address and expiring single-use code in the app.
  4. Open a session. Choose a project, resume or create a conversation, and send a message. Development builds can show permission requests and questions for a response from the paired device.

When the companion is installed, its local administration commands are:

pocketcpu-host version
pocketcpu-host pair --expires 10m
pocketcpu-host devices
pocketcpu-host revoke --device DEVICE_ID

These commands use an already initialized host configuration. Pairing codes and device credentials are secrets; keep them out of screenshots, public issues, and shared logs.

Connection routes

Direct HTTPS

Use a trusted HTTPS address your phone can resolve and reach. Certificate setup and network reachability both matter. The app does not accept invalid certificates or fall back to HTTP.

Optional Tailscale HTTPS

An existing trusted HTTPS address on your tailnet is another route to the same host. PocketCPU does not change VPN settings or display a Tailscale setup prompt just because the app opens.

Experimental self-hosted relay

The outbound bridge lets the host retrieve requests from a separately hosted relay. Both connections use HTTPS, but the relay terminates TLS and can read the traffic. This is not end-to-end encryption or a ready public relay service.

Release requirements

Development builds include structured text conversations, terminal access, tool activity, and permission/question responses. A consumer desktop installer, signing, native Windows runtime validation, and production networking checks remain before public distribution.

For a setup question, open a support issue without credentials, private code, or identifying host information.
